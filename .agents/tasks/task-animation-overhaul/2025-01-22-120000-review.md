# Cinematic animation overhaul with Barba.js transitions and parallax landing sequence

This change transforms the homepage into a layered cinematic experience: a timed landing sequence with 9 parallax layers introduces the site, a fixed navigation bar tracks scroll position, species cards respond to mouse movement with perspective-driven 3D tilt, habitat-themed CSS animations punctuate the scroll journey, and Barba.js wraps all page content for future SPA-style transitions. The globe gains 200 animated flora/fauna sprites (THREE.Points with sine-wave vertex displacement) distributed across 8 ecosystem types. Species pages receive ecosystem-themed CSS custom properties, parallax depth layers on hero and headings, and upgraded spring-physics reveal animations throughout.

**Watch for:** `animateCardZoom` is imported but never called — dead code (confirmed). Barba.js transitions don't clean up or reinitialize ScrollTrigger instances, which will leak triggers and break scroll-driven animations on navigation (confirmed). Navigation items are anchor links to `#` with no click handlers — clicking them navigates nowhere and triggers a page-top scroll (confirmed).

## High-level view

The landing sequence uses a GSAP timeline with two phases: Phase 1 sequentially fades in 9 layers at staggered intervals, Phase 2 separates them with parallax offsets before hiding the container. Scroll is locked via Lenis during the sequence. The handoff depends on the landing DOM being present — if the landing container is missing (e.g. after a Barba page swap back to home), scroll is never explicitly started since Lenis defaults to running, but the landing animation won't replay.

Barba.js is initialized with a single transition (zoom-leave / back-enter), and all content is wrapped with `data-barba` attributes. The setup is structurally incomplete: the homepage canvas, globe, Lenis instance, and all ScrollTrigger registrations live outside the Barba container but depend on DOM that lives inside it. A page swap will leave orphaned GSAP tweens and stale ScrollTrigger instances with references to removed DOM.

The globe's flora/fauna system adds 200 THREE.Points across 8 ecosystem groups, each with a custom ShaderMaterial doing per-particle sine displacement. The 3D hover module is self-contained and re-called in Barba's `afterEnter`, which will accumulate duplicate event listeners on any elements that persist across transitions.

<summary>Issues (7)</summary>

1. **Dead import: `animateCardZoom`** — imported in main.js but never invoked. Remove the import or wire it into the Barba leave transition for species card clicks.
2. **ScrollTrigger leak on Barba transitions** — no `ScrollTrigger.getAll().forEach(t => t.kill())` in the Barba `leave` hook. Navigating away will leave orphaned triggers referencing removed DOM, causing errors and animation glitches on the next page.
3. **Lenis not destroyed/recreated on Barba transitions** — Lenis holds references to the scroll container. After a Barba page swap the scroll container DOM is replaced, but the old Lenis instance still observes the removed element.
4. **Nav links are inert** — `href="#"` with no click handler. Clicking them scrolls to top without navigating to the section. Either add `preventDefault` + `scrollTo` logic, or use anchor IDs matching the overlay sections.
5. **`will-change: transform` on all parallax elements** — the `[data-parallax-speed]` selector promotes every annotated element to its own compositor layer. On index.html that's 6+ overlays and panels. On low-end devices this can exhaust GPU memory and degrade performance. Prefer toggling `will-change` only while the element is in the ScrollTrigger active range.
6. **`init3DHover` accumulates listeners** — called both on init and in Barba `afterEnter`. If Barba navigates back to the homepage without a full reload, elements that survived the swap will have duplicate mousemove/mouseleave handlers. Consider tracking initialized elements or removing old listeners before re-attaching.
7. **Globe click navigates via `window.location.href`** — bypasses Barba entirely. The species page will load as a full-page navigation, defeating the SPA transition. Should either call `barba.go()` or remove Barba for globe-initiated navigation.

## Barba.js integration gaps

Barba.js is initialized with a zoom-out leave animation (opacity 0, scale 1.1) and a back-spring enter animation (opacity 0, y 30). The canvas, Lenis, globe, and nav live outside `data-barba="container"`, which is the correct topology for persisting the 3D scene. The problem is that every `ScrollTrigger.create()` in `setupScrollTrigger` and `setupParallax` binds to DOM elements _inside_ the container (`#scroll-container`, `[data-parallax-speed]` elements). After Barba replaces the container:

1. Those ScrollTrigger instances still exist in GSAP's registry.
2. Their trigger elements are detached from the DOM.
3. On the next scroll event, GSAP queries stale element positions and produces garbage values.

The `afterEnter` hook calls `init3DHover()` but doesn't recreate ScrollTrigger, Lenis, or the overlay UI. A full Barba lifecycle would need `leave` to kill all triggers and `enter`/`afterEnter` to re-register them for the new page.

The globe's click handler uses `window.location.href` (globe.js line 229), performing a full-page navigation that bypasses Barba entirely. Every globe-to-species transition is a hard reload, not a smooth SPA transition.

## Dead code: `animateCardZoom`

`src/transitions.js` exports `animateCardZoom`, which creates a clone overlay that zooms from a card's bounding rect to fill the viewport. Imported in `main.js` line 10 but never invoked. The Barba leave transition uses a generic opacity/scale animation on the container instead. The original design likely intended this as the species card leave transition, but it was replaced without removing the import.

## Navigation bar: display-only, non-interactive

The nav items track active section via scroll progress thresholds in `updateNavActive()`:

```
if (progress > 0.78) activeIndex = 4;      // Vision
else if (progress > 0.50) activeIndex = 3;  // Species
else if (progress > 0.38) activeIndex = 2;  // Numbers
else if (progress > 0.18) activeIndex = 1;  // Globe
```

The active class updates correctly on scroll, but the `<a href="#">` links have no click handler — no `preventDefault`, no scroll-to-section logic, no Lenis `scrollTo` integration. Clicking any nav item navigates to `#`, scrolling to page top and resetting Lenis state. On mobile the nav links are hidden via `display: none`, sidestepping the issue there.

## Parallax `will-change` budget

Every element with `data-parallax-speed` gets:
```css
[data-parallax-speed] {
  will-change: transform;
  transform: translateZ(0);
}
```

On the homepage this applies to 6+ overlay sections and their inner panels, each full-viewport width. Each promoted element costs ~16MB of GPU texture memory at 2x DPR. Six of them is ~96MB for parallax layers alone, before Three.js framebuffers and textures. On mobile devices this can trigger layer demotion by the compositor, causing the jank that `will-change` was meant to prevent. Toggling `will-change` only when entering the ScrollTrigger active range would be more sustainable.
