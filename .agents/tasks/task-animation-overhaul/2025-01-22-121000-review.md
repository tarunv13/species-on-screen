# Cinematic animation overhaul with Barba.js transitions and parallax landing (v2)

All seven concerns from the v1 review have been addressed: `animateCardZoom` is wired into the Barba leave transition for card clicks, ScrollTrigger instances are killed in `leave`, Lenis is destroyed and recreated across transitions, nav links have `lenis.scrollTo()` click handlers with `e.preventDefault()`, `will-change` is toggled dynamically via ScrollTrigger `onToggle`, `destroy3DHover()` uses WeakSet/WeakMap tracking to clean up before re-init, and globe clicks route through `setNavigationHandler()` to `barba.go()`.

**Watch for:** GSAP ticker callback referencing destroyed Lenis instance will throw on every frame between `leave` and `afterEnter` (confirmed). Species page content won't render on Barba navigation because `species-page.js` is a separate entry point whose top-level init code never re-executes after the initial page load (confirmed).

## High-level view

The Barba lifecycle is now structurally correct for homepage-to-homepage navigation: leave kills ScrollTrigger + Lenis, afterEnter recreates both. The gap is in the transition *between* those hooks — `createLenis` adds an anonymous function to `gsap.ticker` but never stores a reference to it, so when Lenis is destroyed in `leave`, the ticker callback continues firing `instance.raf()` on a dead instance until `afterEnter` adds a new one. Each round-trip adds another orphaned ticker callback.

The species pages are built as separate Vite entry points (`src/species-page.js` included via `<script type="module">`). Barba replaces the container's innerHTML but doesn't re-execute `<script>` tags from the fetched page. When a user clicks a globe marker or species card and Barba navigates to a species URL, the new container arrives with empty `#main-content` and a loading placeholder, but `loadSpeciesData()` and `initLenis()` never fire. The species page renders blank.

## Ticker callback leak across Barba transitions

In `createLenis()` (main.js line 99):

```js
gsap.ticker.add((time) => { instance.raf(time * 1000); });
```

This anonymous function captures `instance` in closure. When the leave hook calls `lenis.destroy(); lenis = null;`, the ticker callback still holds a reference to the destroyed Lenis and continues invoking `instance.raf()` ~60 times per second. Lenis's `destroy()` method detaches scroll listeners and nulls internal state, but doesn't patch `raf` to be a no-op — calling it on a destroyed instance is undefined behavior depending on Lenis version (may silently return, may throw on null `this.targetScroll`).

After a navigation cycle (home → species → home), two ticker callbacks will be active: the orphan from the first Lenis and the new one from `createLenis()` in `afterEnter`. Each cycle adds another. The fix is straightforward: store the callback reference as a module-level variable and call `gsap.ticker.remove(fn)` before `lenis.destroy()`.

## Species page inert on SPA navigation

The species pages each include `<script type="module" src="/src/species-page.js">` in their `<head>`. This script runs at page load: it reads `document.body.dataset.species` for the slug, inits Lenis, and calls `loadSpeciesData()` which fetches JSON, renders the page HTML into `#main-content`, then kicks off scroll animations.

When Barba intercepts a navigation to a species page, it fetches the HTML, extracts the `data-barba="container"` element from the response, and replaces the current container with it. The `<script>` tag in `<head>` is never evaluated — Barba explicitly doesn't execute scripts from fetched pages (by design, to prevent double-init). The `afterEnter` hook in main.js only handles `namespace === 'home'`; there's no branch for the `species` namespace.

Result: after a Barba transition to any species page, the user sees the loading placeholder ("Loading species data...") indefinitely. The globe's canvas persists behind it, but no species content renders. Clicking "back" in the browser will trigger a popstate → Barba back-transition, which returns to the homepage correctly (since that lifecycle is fully wired). But the species page itself is dead.

The quickest fix with minimal architecture change: force full-page navigation for species links by adding `data-barba-prevent="self"` to species card `<a>` tags and having the globe's navigation handler use `window.location.href` instead of `barba.go()` when the target is a species page. This preserves the zoom-leave animation on the homepage side while ensuring the species page script executes normally. A proper SPA approach would require extracting `species-page.js`'s init into an importable function and calling it from `afterEnter`.
