# Cinematic Three.js rebuild with semantic TMDB filtering

A full architectural replacement of the Eco-Cinema Observatory site. The previous light-pastel glassmorphism approach is replaced by a dark cinematic Three.js experience on the main page (fixed full-screen WebGL canvas with scroll-driven camera, post-processing bloom and film grain, instanced-mesh data columns on a globe) and a 7-section academic content structure on species pages (Hero, Science, On Screen, Methodology, COM-B, Evidence, References). Alongside the visual rebuild, the TMDB data pipeline gains semantic filtering (genre-based trap rejection, relevance scoring, narrative technique classification) that eliminates contaminated results like war films and martial arts movies that previously appeared alongside legitimate wildlife content.

**Watch for:** Two concurrent `requestAnimationFrame` loops run unconditionally and never stop (confirmed). Accessibility landmarks, roles, and skip-to-content links removed from the main page without replacement (confirmed). Globe raycasting event listeners never cleaned up (confirmed).

## High-level view

The main page is now a single fixed Three.js canvas with HTML overlays faded in and out by scroll progress. Scroll distance is provided by an empty 600vh div; GSAP ScrollTrigger translates scroll position into a 0-1 progress value that drives both camera keyframe interpolation and overlay opacity. The architecture depends on both the cinematic engine's render loop and a separate globe update loop running simultaneously every frame, with no visibility gating.

The globe shifts from a decorative procedural-texture sphere with OrbitControls to a data-visualization component: instanced cylinder columns whose height reflects media coverage volume, loaded at runtime from the species JSON files. Raycasting hit targets are the 0.015-radius cylinders, which are very small on mobile compared to the previous 0.02-radius spheres.

The TMDB pipeline now searches with multiple wildlife-scoped queries per species, rejects results whose genre_ids match action/crime/war/thriller (unless the overview contains nature keywords), scores remaining results on keyword density and genre affinity, and enriches the top 15 with director credits and backdrops. The output JSON schema is extended with COM-B, methodology, evidence, and reference fields that the species pages consume.

Species pages are restructured around 7 academic sections rendered from the enriched JSON. The 4 Research Questions displayed on species pages (from `fetch-tmdb-data.js`) use completely different wording than the 4 RQs hardcoded in `index.html`, creating contradictory research framing between pages.

<summary>Issues (6)</summary>

1. **Dual animation loops never pause** — CinematicEngine runs a perpetual rAF render loop and main.js starts a second rAF loop for globe updates. Neither pauses when the tab is backgrounded or when content is off-screen. Consolidate into a single loop, or at minimum gate rendering behind `document.visibilityState`.
2. **Accessibility regression on main page** — The previous version had nav landmarks, aria-labels, ARIA roles on the species gallery, and a globe role="img" with accessible description. The new version has only a single `aria-hidden` attribute. Add landmark roles, screen-reader announcements for scroll sections, and keyboard-accessible species navigation.
3. **Globe event listeners leak** — `mousemove`, `click`, `mouseenter`, `mouseleave` listeners on the canvas are never removed. If the globe is ever reinstantiated or the page transitions, these accumulate. Store handler references and provide a `dispose()` method.
4. **No JS-off fallback** — The old codebase had a `.js-loaded` progressive enhancement pattern that kept content visible if JS failed. The new page is entirely JS-dependent with an empty canvas and invisible overlays when scripts don't execute. Consider a `<noscript>` block with essential content.
5. **Research Questions text diverges between HTML and JSON** — The 4 RQs hardcoded in `index.html` don't match the `RESEARCH_QUESTIONS` array in `fetch-tmdb-data.js`. One says "visually represented in contemporary documentary and fiction film" while the other says "evidence of digital content helping enhance awareness." These describe different research scopes entirely (video games vs screen representation).
6. **547KB main bundle** — Three.js, GSAP, and all post-processing passes ship as a single chunk. Code-splitting or dynamic importing the 3D layer behind the loading screen would reduce initial load.

## Dual render loops and resource cost

CinematicEngine starts a `requestAnimationFrame` loop in its constructor (`_startLoop`) that runs the EffectComposer every frame regardless of scroll activity or tab visibility. Separately, `main.js` starts a second `requestAnimationFrame` loop (`startGlobeUpdate`) that calls `globe.update(delta)` every frame for rotation and raycasting.

```javascript
// cinematic-engine.js - loop 1 (always renders)
_startLoop() {
  const animate = () => {
    this._animationId = requestAnimationFrame(animate);
    this.composer.render();
  };
  animate();
}

// main.js - loop 2 (always ticks)
function startGlobeUpdate() {
  function tick() {
    requestAnimationFrame(tick);
    if (globe) globe.update(delta);
  }
  tick();
}
```

The cinematic engine has a `dispose()` method that cancels its animation frame, but nothing calls it. The globe loop has no cancellation mechanism at all. On mobile devices this burns GPU cycles continuously even when the user is reading a species page in another tab. The previous implementation used an IntersectionObserver to pause the globe when off-screen; that pattern is gone.

## Accessibility removal

The base branch had: `<nav aria-label="Section navigation">` with labeled dots, `role="toolbar"` on the species filter bar, `role="img" aria-label="Interactive 3D globe..."` on the globe container, and `role="listitem"` on species cards. The new version removes all of these without replacement. The overlay-driven architecture makes content invisible to assistive tech by default (`visibility: hidden`, `pointer-events: none`) and only reveals it during narrow scroll windows that screen readers cannot navigate.

The species gallery links inside `.overlay--species` retain semantic `<a>` elements, but there is no mechanism to reach that content without scrolling through 600vh of empty space — a barrier for keyboard-only and screen-reader users.

## Globe interaction hit targets

The raycaster tests against `this.columnMeshes` (cylinder bodies of 0.015 radius at globe scale) but not the base rings. At typical viewing distances these are a few pixels wide. The previous implementation used 0.02-radius spheres. On mobile/touch devices, these columns will be difficult to tap without increasing the hit area via a larger invisible collision mesh or by testing against the base rings as well.

## Research Questions content divergence

The `index.html` overlay hardcodes 4 RQs:
- RQ1: "How are endangered species visually represented in contemporary documentary and fiction film?"
- RQ3: "How does the volume and nature of screen representation correlate with public conservation awareness?"
- RQ4: "Can a COM-B behavioural framework explain the gap between media exposure and conservation action?"

Meanwhile `RESEARCH_QUESTIONS` in `fetch-tmdb-data.js` (rendered on every species page) uses different wording and scope:
- RQ1: "What is the evidence of digital content helping enhance awareness..."
- RQ3: "How can non-commercial video games be used to engage more with biodiversity..."
- RQ4: "What are the best practices to evaluate the effectiveness of digital content..."

These describe fundamentally different research programmes. A visitor navigating from the main page to a species page encounters contradictory framing. One source of truth should drive both.
