# Globe-first immersive interface with safari deep-dive

The site has been transformed from a scroll-driven experience into a globe-as-app interface. The Three.js globe fills the viewport after a cinematic fly-in, floating frosted-glass cards are positioned via world-to-screen projection at species locations, and clicking a card triggers a 4-phase GSAP transition into a parallax safari scene with comic-strip storytelling. The old scroll architecture (Lenis/ScrollTrigger/Barba/OverlayUI) is removed from the main interface and ScrollTrigger is re-introduced locally within the safari scene. Ten species JSON files are enriched with `safari_scene` and `comic_strip` fields.

**Watch for:** CSS injection via unescaped safari_scene color values interpolated into style attributes (confirmed); Safari scene never scrolls to top on re-entry because scroll position isn't reset (confirmed); Globe drag rotation continues accumulating while camera is zoomed into safari, so returning may show an unexpected orientation (likely); no timeline abort on failed safari fetch leaves canvas at opacity 0.3 (confirmed).

## High-level view

The CinematicEngine owns camera position via a `_cameraTarget` vector updated every frame with `lookAt`, and exposes `flyCamera()` returning a nestable GSAP timeline. This lets main.js compose multi-phase transitions as declarative timelines without touching the render loop.

Globe.js replaces scroll-driven auto-rotation with pointer-event drag rotation applying per-frame inertia damping. It exposes `getScreenPositions(camera)` projecting species centroids to screen coordinates, and `getSpeciesPosition(slug)` for zoom targets. The update loop runs unconditionally — including while the safari overlay is active — so accumulated inertia can drift the globe orientation before the user returns.

The safari transition is a single GSAP timeline with 4 phases gated by an `isTransitioning` boolean. The flag prevents concurrent starts but doesn't abort in-progress timelines, and doesn't handle the failure case where `SafariScene.enter()` silently returns (network error) leaving the canvas faded.

SafariScene renders the habitat experience as innerHTML, creates a scoped Lenis instance, and registers ScrollTrigger instances for panel reveals. It reads `safari_scene` colors from JSON for the parallax hero palette with a fallback to hardcoded `HABITAT_PALETTES`. The color values are interpolated directly into a `style` attribute without sanitization, creating a CSS injection surface if the data source is ever untrusted.

Species JSON includes pre-authored `comic_strip` arrays with a fallback auto-generation path, providing backward compatibility for future species that lack the field.

<summary>Issues (7)</summary>

1. **CSS injection in safari hero style attribute** — `safari_scene.sky_gradient`, `silhouette_color`, `mid_color`, `foreground_color` are interpolated into a `style="--sky-top: ${skyTop}; ..."` attribute without escaping. A value like `#000; } * { display:none } .x {` injects arbitrary CSS. Sanitize with a color-format regex or escape the values.
2. **Safari scroll position not reset on re-entry** — `enter()` clears innerHTML and rebuilds DOM but never calls `this.container.scrollTop = 0`. Second species visit starts at the scroll offset left by the previous one.
3. **No timeline kill on failed safari enter** — If `SafariScene.enter()` fails (fetch error), it returns silently but the GSAP timeline has already set canvas opacity to 0.3 and activated the safari container. No rollback occurs. Store the timeline reference and kill it on error.
4. **Globe rotation accumulates during safari** — `globe.update(delta)` applies inertia every frame regardless of app state. A fast spin before clicking a card continues rotating the globe behind the safari overlay; returning shows an unexpected orientation.
5. **Memory growth across safari enter/exit cycles** — Each `enter()` fetches JSON again (globe already has it in `speciesDataCache`) and creates new Lenis/ScrollTrigger instances. `exit()` kills triggers but never calls `ScrollTrigger.refresh()`. Over many cycles, GSAP's internal measurement cache may grow.
6. **Floating cards race condition** — `waitForSpeciesData()` fires `initFloatingCards()` when `speciesDataCache` has any keys. If some species resolve after the polling threshold, those species never get cards. Wait for all promises to settle or re-create cards on cache changes.
7. **Texture load failure with no user feedback** — If the Earth texture CDN (unpkg) is unreachable, the globe silently falls back to a flat blue sphere after the loading screen has already dismissed.

## CSS injection in safari style attributes

SafariScene._render injects color values into a style attribute:

```js
style="--sky-top: ${skyTop}; --sky-bottom: ${skyBottom}; --silhouette-color: ${silhouetteColor}; --mid-color: ${midColor}; --foreground-color: ${foregroundColor};"
```

These values come from `data.safari_scene.sky_gradient[0]` etc. without any escaping or format validation. While `escapeHtml()` is applied to text content and `src` attributes throughout the rest of the render method, style attribute context requires different escaping — HTML entity encoding doesn't prevent CSS injection within an already-open attribute value. A regex check for `/^#[0-9a-fA-F]{3,8}$/` on each color value before interpolation would close this. The threat model is low today (first-party static JSON) but becomes real if the data pipeline ever accepts external contributions. Confidence: **confirmed**.

## Transition state machine and failure modes

The zoom-in transition in `onCardClick()` builds a timeline that:
- At 0ms: hides floating cards
- At 600ms: starts camera flight
- At 1400ms: fades canvas to 0.3 opacity
- At 1600ms: activates safari container, calls `safariScene.enter(slug)`
- At 2000ms: sets `isTransitioning = false`

If `enter()` fails (the `catch` block just returns), the timeline has already executed phases 1-3 irreversibly. The canvas sits at opacity 0.3, the safari container is active but empty, and `isTransitioning` becomes false at 2000ms allowing the user to click another card into the same broken state. The fix is to store the timeline, and in the error path: kill the timeline, reverse canvas opacity, deactivate the container, and re-show cards. Confidence: **confirmed** (error path in safari-scene.js line 57 just returns, main.js doesn't observe the result).

## Globe inertia during safari

```
this._velocity.x *= this._damping;  // 0.95
this.group.rotation.y += this._velocity.x;
```

This runs every frame in `globe.update()`. Damping 0.95 means velocity halves every ~14 frames (~230ms at 60fps). A moderate drag velocity of 0.1 rad/frame would produce ~2 radians of additional rotation over 50 frames before becoming negligible. The camera returns to a fixed world position `(0, 0.3, 5.5)` but the globe group has rotated, so the user sees different geography than what was visible when they clicked. Zeroing velocity when the transition starts (in `onCardClick`) would fix this. Confidence: **likely**.

## Floating cards creation timing

```js
function waitForSpeciesData() {
  const check = () => {
    if (Object.keys(globe.speciesDataCache).length > 0) {
      initFloatingCards();
    } else {
      setTimeout(check, 200);
    }
  };
  check();
}
```

`_loadMediaCounts()` uses `Promise.all` over 10 fetches. On fast networks they resolve together, but the architecture doesn't guarantee atomicity. The polling condition (`> 0` keys) fires on the first resolution. Cards are created from whatever keys exist at that moment and never updated. If a species resolves 300ms later, it gets no card. A more robust approach: expose a promise from Globe that resolves when all species are loaded, or check `Object.keys(...).length === SPECIES_FILES.length`. Confidence: **likely**.

## Layer toggle naming asymmetry

The buttons use `data-layer="species"` / `"habitat"` / `"threats"` but `setLayer()` internally branches on `'media' || 'species'`, `'habitat'`, `'protected_areas' || 'threats'`. This works because the conditions use `||` — but if a developer later adds a button for `"media"` or `"protected_areas"` expecting different behavior than `"species"` or `"threats"`, they'll get silent aliasing. The naming should be unified to one vocabulary.
