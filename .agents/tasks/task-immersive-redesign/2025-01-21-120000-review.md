# Immersive redesign: dark-to-light theme, research questions removal, and species page enrichment

This change transforms the Eco-Cinema Observatory from a dark academic-styled site into a light, scroll-driven immersive experience. It removes all research question content (RQ1-RQ4, methodology sections, `methodology_notes`) from every layer of the stack: JSON data, HTML templates, JS renderers, CSS, and the data pipeline script. The visual overhaul replaces the procedural Fresnel-shader globe with a real NASA Blue Marble texture, removes the film grain post-processing pass, rewrites all color palettes from dark (#0a0a0f) to light (#fafaf8), adds Lenis smooth scrolling, introduces comic-strip panels and photo galleries on species pages, and enriches all 10 species JSON files with `data_sources`, `interesting_facts`, and `photos` fields. The overlay system is restructured from 6 sections (including research/methodology) to 5 (adding "By the Numbers"), with spring-animated stagger transitions.

**Watch for:** Unescaped URLs interpolated into HTML attributes create an XSS surface in species-page rendering (confirmed). The globe's Earth texture loads from `unpkg.com` with no fallback, so a CDN outage produces a blank sphere (confirmed). Overlay scroll ranges for "numbers" and "species" overlap at 0.44, meaning both sections receive pointer events simultaneously at that progress value (confirmed).

## High-level view

The research-question removal is complete across all layers - data, templates, renderers, CSS, and the pipeline script.

The main page replaces the dark Three.js scene with a light-themed equivalent: film grain shader deleted, particles shifted to green/gold with normal blending, bloom softened, and the custom Fresnel globe swapped for a `MeshStandardMaterial` with a remote NASA Blue Marble texture. The texture loads from unpkg.com with no error callback, so CDN failures produce a blank sphere. Lenis smooth scrolling connects to GSAP ScrollTrigger via ticker integration.

Species detail pages gain `renderComicStrip` (4-panel narrative grid), `renderPhotos` (gallery with parallax), and `renderInterestingFacts` (cards with citations). The science section now shows inline source citations from `data_sources` in the JSON. However, URLs are inconsistently escaped - `renderPhotos` uses `escapeHtml()` on photo URLs, but `renderHero` and `renderComicStrip` interpolate the same URLs raw into style attributes and img src.

The overlay timing system drops from 6 to 5 sections with tighter packing. The "numbers" and "species" ranges overlap at progress 0.44, creating a ~3% scroll window where both overlays accept pointer events.

<details>
<summary>Issues (5)</summary>

1. **Unescaped URLs in background-image styles** — `bgImage` and `heroPhoto` are interpolated raw into `style="background-image: url('...')"` and `<img src="...">` without `escapeHtml()`. A JSON payload with a crafted URL (containing single-quote or closing paren) could break out of the attribute. Escape these or validate URL format before interpolation.
2. **CDN-dependent globe texture with no fallback** — The Earth texture loads from `unpkg.com/three-globe/example/img/earth-blue-marble.jpg`. If the CDN is unreachable or the path changes, the globe renders as a featureless grey sphere with no error indication to the user. Add an `onerror` handler on the texture load or bundle a low-res fallback.
3. **Overlay range overlap at 0.44** — The "numbers" range reaches full visibility at 0.44, and "species" fade-in also starts at 0.44. Both overlays are simultaneously visible with `pointer-events: auto` during the crossfade, which can cause click-target confusion.
4. **`posterThumb` img src not escaped** — The TMDB poster path is interpolated into `<img src="${posterThumb}"` without escaping. While currently TMDB paths are safe, this is inconsistent with the `escapeHtml()` applied to the same photo URLs in `renderPhotos`.
5. **No `onerror` fallback for globe texture** — `THREE.TextureLoader.load()` is called without an error callback. Network failures silently produce a blank material.

## Globe texture loading and CDN dependency

The procedural Fresnel shader (60+ lines of GLSL) is replaced by a single `TextureLoader.load()` call:

```js
const earthTexture = textureLoader.load(
  'https://unpkg.com/three-globe/example/img/earth-blue-marble.jpg'
);
```

If unpkg goes down or the `three-globe` package removes that example asset, the globe renders with a blank `MeshStandardMaterial` (grey appearance against the cream background). There is no user-visible error, no retry, and no fallback texture. The atmosphere halo (recolored to warm white with `NormalBlending`) was designed assuming visible continents underneath, so a grey fallback sphere would look especially wrong - a bright halo around a featureless blob.

## URL escaping asymmetry in species-page templates

`renderPhotos` applies `escapeHtml()` to `photo.url` before inserting it into `<img>` attributes. Three other interpolation sites skip escaping for the same data:

1. `bgImage` in `renderHero`: `url('${bgImage}')` — sourced from `data.photos[0].url`
2. `heroPhoto` in `renderComicStrip`: `url('${heroPhoto}')` — same source
3. `posterThumb` in `renderComicStrip`: `<img src="${posterThumb}"` — sourced from TMDB `poster_path`

The data comes from first-party JSON committed to the repo, so exploitation currently requires a supply-chain compromise. But the inconsistency is the issue: the same `photo.url` value is escaped in one function and raw in another. A URL containing `')` followed by arbitrary CSS, or `"><script>` in the img case, would break out of the attribute context if data ever comes from an untrusted source.

## Overlay scroll-range overlap

```
numbers:  [0.38, 0.44, 0.50, 0.54]
species:  [0.44, 0.52, 0.75, 0.82]
```

Between progress 0.44 and 0.50, both overlays have opacity > 0.01 (both visible). Around 0.47, the species overlay's opacity crosses 0.5, gaining `pointer-events: auto`, while "numbers" retains `pointer-events: auto` until its fade-out starts at 0.50. The dual-pointer-events window spans roughly 21vh of scroll (700vh * 0.03), which could cause click-target confusion during the transition.

## Comic strip data_sources key proliferation

The `renderComicStrip` function checks for 8 different `data_sources` keys to populate the "Under Threat" panel:

```js
${data.data_sources && data.data_sources.habitat_loss ? ... : ''}
${data.data_sources && data.data_sources.range_loss ? ... : ''}
${data.data_sources && data.data_sources.decline ? ... : ''}
// ...5 more variants
```

Each species has a unique threat-stat key (tiger: `habitat_loss`, polar bear: `sea_ice_loss`, coral: `reef_loss`). Adding a new species requires updating the rendering code to handle its specific key. A standardized `primary_threat_stat` key in each JSON, or iterating over non-standard keys in `data_sources`, would decouple the renderer from the data schema.
