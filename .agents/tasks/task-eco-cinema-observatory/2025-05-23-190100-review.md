# Scroll-driven visual prototype for Eco-Cinema Observatory

A greenfield static site built with Vite, Three.js, and GSAP that delivers the full single-page scroll experience: ambient particle hero, interactive 3D globe with biodiversity hotspot markers, glass-morphism content cards, animated tiger species profile, and a vision roadmap. GitHub Actions workflow handles deployment to Pages. The aesthetic is light ecological pastels with contemplative pacing controlled by ScrollTrigger scrub timelines.

**Watch for:** The production bundle ships at 656 KB (gzip 181 KB) because Three.js is bundled monolithically with no code-splitting (confirmed). The globe animation loop runs unconditionally even when the section is off-screen, wasting GPU frames (confirmed). Several scroll-animated elements start at `opacity: 0` in JS with no CSS fallback, so the page is partially invisible if JavaScript fails to load (confirmed).

## High-level view

The build and deploy pipeline is correctly configured for GitHub Pages with the right `base` path, permissions, and artifact upload. The friction point is the 656 KB chunk that triggers Vite's own size warning and will slow first paint on mobile connections.

Three.js handles the globe with a procedural canvas texture, a custom atmosphere shader, and OrbitControls. The rendering loop never pauses, even when the globe container is scrolled out of view. On mobile this means continuous GPU work for a section the user scrolls past in seconds.

GSAP ScrollTrigger orchestrates all section transitions with scrub-linked timelines and reduced-motion is respected at every entry point. The gap is that initial element visibility depends entirely on `gsap.set()` calls in JS; if JS partially fails mid-init, elements remain stuck at opacity 0 with no recovery path.

Accessibility covers the basics (aria-hidden on decorative elements, aria-labels on nav dots, semantic headings) but the scroll-nav dots lack focus styles, the globe canvas has no text alternative, and concept card interactions are mouse-only.

## Bundle weight and load strategy

The production build outputs a single 656 KB JS chunk (181 KB gzip). Three.js alone accounts for the vast majority. For a page whose above-the-fold content is pure HTML text and a lightweight 2D canvas particle system, there's no reason the WebGL bundle needs to block first paint. A dynamic `import('./globe.js')` triggered when the globe section enters the viewport (or on idle) would let the hero section render hundreds of milliseconds earlier on 3G/4G connections.

## Globe rendering lifecycle

`initGlobe()` calls `animate()` which loops via `requestAnimationFrame` indefinitely from DOMContentLoaded. The globe section occupies roughly 60vh in the middle of the page. On a phone the user might spend 80% of their session in sections where the globe is off-screen, yet the GPU is compositing every frame. A simple IntersectionObserver on `globe-container` that calls `cancelAnimationFrame` when invisible and restarts when visible would eliminate wasted work. The `destroyGlobe()` export exists but is never called from anywhere in the codebase.

```javascript
// globe.js animate() runs unconditionally:
function animate() {
  animationId = requestAnimationFrame(animate);
  // ...
  renderer.render(scene, camera);
}
```

## JS-gated visibility

`scroll-animations.js` sets elements to opacity 0 and offset positions via `gsap.set()` before their scroll triggers register:

```javascript
gsap.set(globeContainer, { opacity: 0, scale: 0.9 });
gsap.set(heading, { opacity: 0, y: 30 });
```

If any error between the `gsap.set()` calls and the corresponding `gsap.to()` timelines prevents the ScrollTrigger from firing (a race condition, a library version mismatch, a CSP block on eval), those elements stay invisible permanently. The fix is to apply the hidden state via a CSS class that's only present when a JS flag on `<body>` confirms the animation system loaded, or to use a CSS default of visible and let GSAP override only when ready.

## Accessibility gaps

The `.scroll-nav__dot` anchors are rendered as tiny circles with no `:focus-visible` outline or ring. Keyboard users tabbing through the page see no indication of which dot is focused. The `:hover` rule changes opacity but `:focus` is unaddressed.

The globe `<canvas>` element appended by Three.js provides no alternative text. A screen reader user encounters a blank canvas with no context. An `aria-label="Interactive 3D globe showing five biodiversity hotspot locations"` on the container div, or a visually-hidden description paragraph, would close the gap.

The concept cards in `concept-section.js` use `mouseenter`/`mouseleave` for the active class but have no keyboard equivalent (`focusin`/`focusout`), so the active styling never appears for keyboard users navigating through the cards.

## Resize handler asymmetry in hero particles

`hero.js` attaches a `resize` listener with an anonymous arrow function and never removes it. `destroyHero()` cancels the animation frame but leaves the listener attached. `globe.js` correctly removes its resize listener in `destroyGlobe()`. The asymmetry means the hero cleanup path leaks a listener if the page ever supports teardown (SPA routing, HMR in dev mode).
