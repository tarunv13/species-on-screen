# Scroll-driven visual prototype for Eco-Cinema Observatory (v2)

All five issues and two improvements from the v1 review have been addressed. The globe now lazy-loads via dynamic `import()` and pauses rendering when off-screen via IntersectionObserver. The JS-fallback uses a `.js-loaded` body class pattern. Scroll-nav dots have `:focus-visible` styles. The globe container carries `role="img"` with an `aria-label`. Concept cards listen for `focusin`/`focusout`. The hero resize handler is stored and removed in `destroyHero()`.

**Watch for:** The JS-dependent visibility CSS rule is a no-op that doesn't actually protect against the mid-init failure scenario it was designed for (confirmed). Concept cards added keyboard event handlers but remain unreachable by keyboard because `<article>` elements aren't natively focusable and no `tabindex` is present (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The code-splitting fix is well implemented. `main.js` dynamically imports `globe.js` via an IntersectionObserver with a 200px rootMargin, so the Three.js bundle never blocks initial paint. The globe's own IntersectionObserver pauses the render loop when the container scrolls out of view, eliminating wasted GPU frames.

The `.js-loaded` body class is added before any `gsap.set()` calls fire, but the corresponding CSS rule only sets `visibility: visible` — which is already the default. The intended protection (content remains visible if JS errors mid-init) isn't achieved because the problem is inline `opacity: 0` set by GSAP, not `visibility: hidden`. If GSAP's `set()` succeeds but ScrollTrigger fails, elements stay at opacity 0 regardless of the CSS rule.

The concept card focusin/focusout handlers are present, but `<article>` elements are not in the tab order. Without `tabindex="0"` on the cards, keyboard users will never trigger those events. The fix is half-applied.

## JS-dependent visibility gap

The CSS rule:

```css
.js-loaded .section__heading,
.js-loaded .globe-container,
/* ... */ {
  visibility: visible;
}
```

…sets the property to its default value. There's no corresponding `visibility: hidden` base rule for these elements. The actual hiding is done by GSAP inline styles (`opacity: 0`), which the CSS `visibility` property cannot override. The mid-init failure path — `gsap.set()` executes, sets opacity to 0, then an error prevents ScrollTrigger from revealing — still leaves elements invisible.

A working pattern would be:

```css
.js-loaded .section__heading { opacity: 0; }
```

…with the `gsap.set()` calls removed, since CSS handles the initial hidden state. Then if JS errors after adding `.js-loaded`, a catch block or `window.onerror` handler removes the class, and elements revert to their default `opacity: 1`.

## Concept card keyboard reachability

`concept-section.js` adds `focusin`/`focusout` listeners, but `<article>` elements are not in the default tab order. Pressing Tab from the preceding section skips directly past the cards unless they have `tabindex="0"`. Adding `tabindex="0"` to each `<article class="glass-card concept-card">` in `index.html` completes the fix.
