# Consolidated species data, species page renderer, and globe layer system

This change enriches 10 species JSON files with real URLs, cultural depth, COM-B barriers with citations, and protected area coordinates. It adds a full species page renderer (`species-page.js` + `species-page.css`) that fetches JSON and builds a scrollytelling narrative with hero images, comic panels, galleries, COM-B cards, TMDB media, and expandable cultural cards. The homepage (`index.html`) is rebuilt as a cinematic Three.js experience with scroll-driven camera, overlay system, and a globe with togglable layers (media columns, habitat discs, protected area markers). A Vite multi-page build and Barba.js page transitions tie the pages together.

**Watch for:** The species page fetches data using a hardcoded path (`/species-on-screen/data/`) that will break in dev mode where base is `/` (confirmed). The globe uses `import.meta.env.BASE_URL` correctly, creating an inconsistency. CSS hides all animated content behind `opacity: 0` until GSAP fires ScrollTrigger — if GSAP fails silently (no uncaught error), content below the fold stays invisible (likely).

## High-level view

The species page renderer consumes JSON through 12 render functions, each defensively checking for its expected keys before emitting HTML. The data format across all 10 JSON files is consistent, and the renderer handles both the new `com_b` object format (with per-claim `source_url`) and the older `root_causes_comb` string array format via fallback. No data-format runtime errors are expected assuming the fetch succeeds.

The globe has been rewritten into a class-based component with 31 data columns, habitat discs, and protected area markers loaded from species JSON. Layer toggling, raycasting, and the info panel are wired correctly between the HTML elements in `index.html` and the Globe class methods. The globe fetches all 10 JSON files at init using `import.meta.env.BASE_URL` (correct in both dev and prod).

The critical runtime concern is the fetch path in `species-page.js` — hardcoded to `/species-on-screen/data/` — which 404s in dev mode. In production builds this works because Vite's `base` is `/species-on-screen/`. Local development of species pages will show the "Unable to load species data" error message.

The CSS visibility pattern (`opacity: 0` on `.sp-loaded` elements, animated in by GSAP ScrollTrigger) has a partial fallback: a global error listener removes the hiding class. But this won't catch scenarios where GSAP loads but ScrollTrigger doesn't fire (e.g., scroll container height miscalculation). The `prefers-reduced-motion` check also removes the class, which is good accessibility.

## Fetch path mismatch between species-page.js and globe.js

The globe fetches species data via `import.meta.env.BASE_URL`:

```js
const basePath = import.meta.env.BASE_URL || '/';
const res = await fetch(`${basePath}data/${slug}.json`);
```

The species page renderer uses a hardcoded absolute path:

```js
const response = await fetch(`/species-on-screen/data/${slug}.json`);
```

In production (where Vite sets `BASE_URL` to `/species-on-screen/`), both resolve correctly. In dev mode, Vite sets `BASE_URL` to `/`, so the globe fetches `/data/tiger.json` (correct — `public/data/tiger.json` is served there by Vite's dev server), while the species page fetches `/species-on-screen/data/tiger.json` (404). Species pages cannot be developed locally without fixing this line.

## CSS visibility: GSAP dependency for content display

The species page CSS sets `opacity: 0; transform: translateY(25px)` on all major content elements when `.sp-loaded` is present on `<body>`. This class is added after successful JSON fetch. GSAP's `initAnimations()` then animates elements visible via ScrollTrigger.

The fallback chain:

```js
window.addEventListener('error', () => document.body.classList.remove('sp-loaded'));
```

This removes the hiding class on uncaught errors. But `window.addEventListener('error')` won't fire if GSAP loads successfully and ScrollTrigger simply never triggers (e.g., the `start: 'top 85%'` threshold is never reached because the viewport is unusually tall). In that edge case, content below ~85% viewport height remains at `opacity: 0`.

The `prefers-reduced-motion` check in `initAnimations()` correctly removes the class and exits early, ensuring accessibility.

## Barba.js and species card click interaction

The `data-barba-prevent="self"` attribute on species card links tells Barba not to intercept them. The manual `setupSpeciesCardClicks()` handler uses event delegation on `document` to catch `.species-card` clicks, play a zoom animation, then navigate via `window.location.href`. 

The fragility: Barba also installs a delegated click handler on the document. Both handlers listen at the document level. If Barba's handler fires first (despite `prevent`), it could call `preventDefault()` before the manual handler runs. In practice, Barba respects `data-barba-prevent` and returns early, but this depends on Barba's internal implementation detail. A safer approach would be to not initialize Barba at all if it's not performing actual client-side transitions.
