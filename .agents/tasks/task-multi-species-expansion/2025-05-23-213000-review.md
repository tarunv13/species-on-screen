# Multi-species expansion with TMDB media integration

The Eco-Cinema Observatory evolves from a single tiger profile into a ten-species gallery backed by TMDB movie data. The homepage gains a filterable card grid linking to individual species pages, each rendered client-side from static JSON. The globe scales from 5 hotspot markers to 31 ecosystem-coded locations. A Node script fetches TMDB data at build-preparation time and writes it to `public/data/`. The Vite config grows multi-page input via filesystem enumeration of `species/*.html`, and the deploy workflow fixes a broken environment URL expression.

**Watch for:** The TMDB fetch script contains a hardcoded API key committed to version control (confirmed). Species pages render all content client-side from JSON with no static HTML fallback, meaning search engines and users with JS disabled see only "Loading species data..." (confirmed). The `species-page.js` entry point uses `gsap.set()` to hide elements at opacity 0 without the `js-loaded` safety net the homepage employs, so a partial JS failure leaves sections invisible (confirmed).

## High-level view

The TMDB fetch script hardcodes a valid API key (`ab7c1810da1a84fbc50d3fe313f42a72`) directly in source. This key is now in git history regardless of future removal and should be rotated and moved to an environment variable before the script is run in any shared or CI context.

Species pages are fully client-rendered: the HTML shell contains only a loading message and a `<script>` tag. The `species-page.js` fetches JSON at runtime and injects all DOM content via `innerHTML`. This means no content is crawlable without JS execution, and the JSON-LD structured data in the `<head>` provides only a generic stub (`"description": "Species profile for tiger"`) that doesn't carry the rich content the page eventually renders.

The filter system uses GSAP to animate card visibility transitions with `onComplete` callbacks setting `display: none`. Filter state is coupled to animation completion, creating a race condition if the user clicks a second filter before the first animation finishes.

1. **Hardcoded TMDB API key in source** — `scripts/fetch-tmdb-data.js` line 8 contains a plaintext API key committed to git. Rotate the key, read it from `process.env.TMDB_API_KEY`, and document the required env var in the README or a `.env.example`.

3. **No JS-failure safety net on species pages** — `species-page.js` calls `gsap.set(panel, { opacity: 0 })` during `initAnimations()` with no `.js-loaded` class guard or `prefers-reduced-motion` CSS override at the page level (the `!important` override only fires on `prefers-reduced-motion`). 4. **Filter animation race condition** — In `species-gallery.js`, filtering cards uses `gsap.to()` with an `onComplete` callback to set `display: none`. If a user clicks a second filter before the first animation completes, cards can end up in inconsistent display/opacity states because the previous tween isn't killed.
5. **XSS via `innerHTML` if JSON is tampered** — `species-page.js` builds HTML strings from JSON data using `escapeHtml()` for text content, but the `statusClass()` function output is interpolated directly into class attributes (`sp-badge--${statusClass(...)}`). If the `iucn_status` field contains quotes or special characters, this breaks the attribute. Low risk since data is first-party static JSON, but the pattern is fragile.
6. **TMDB image URLs loaded over uncontrolled CDN** — Poster images are loaded from `image.tmdb.org` with no fallback timeout or error handler on `<img>` tags. If TMDB CDN is slow or blocked, the media grid shows broken images with no graceful degradation beyond the `alt` text.

## Hardcoded TMDB API key

The fetch script at `scripts/fetch-tmdb-data.js` opens with:

```javascript
const TMDB_API_KEY = 'ab7c1810da1a84fbc50d3fe313f42a72';
```

This key is now in git history on a public repository. TMDB API keys have rate limits and can be revoked, but the exposure pattern is the concern: any build-time secret committed to source is a credential management failure. The script is designed to run locally or in CI before deployment (`npm run fetch-data`), so reading from `process.env` with a clear error message when absent is the appropriate pattern.

## Client-rendered species pages and SEO

Each species HTML file (`species/tiger.html`, etc.) ships with this body:

```html
<main id="main-content">
  <div class="species-page-loading">Loading species data...</div>
</main>
```

The `species-page.js` module fetches `/species-on-screen/data/${slug}.json` and replaces the entire `<main>` contents via `innerHTML`. The `<head>` contains Open Graph tags and JSON-LD, but these carry only stub descriptions (`"Species profile for tiger"`). Google can execute JS for indexing, but relies on rendered content within a timeout window, and social media link previews never execute JS.

For a static site deployed to GitHub Pages, the most natural fix is a build-time prerender: run the renderer during `vite build` (or a post-build step) and inject the HTML into each species file. Alternatively, promote the critical metadata (name, status, population, habitat type) into the static HTML so that the page has meaningful content even before JS executes.

## Species page animation safety

Species pages don't implement the homepage's `js-loaded` body class pattern. `species-page.js` calls `initAnimations()` after rendering, which uses `gsap.set()` to hide panels:

```javascript
gsap.set(panel, { opacity: 0, y: 30 });
gsap.to(panel, {
  opacity: 1, y: 0, /* ... */
  scrollTrigger: { trigger: panel, start: 'top 85%' }
});
```

The `species-page.css` includes a `@media (prefers-reduced-motion)` rule that forces `opacity: 1 !important`, which protects that subset of users. But for standard users, if any error occurs between `gsap.set()` and the ScrollTrigger registration (or if ScrollTrigger fails to fire because the element is already in the viewport when set), content stays invisible with no recovery path.

## Filter animation state management

`species-gallery.js` animates cards in and out on filter change:

```javascript
gsap.to(card, {
  opacity: 0, y: -10, scale: 0.95, duration: 0.25, ease: 'power2.in',
  onComplete: () => { card.style.display = 'none'; }
});
```

If the user clicks "Ocean" then immediately clicks "All" within 250ms, the hide animation's `onComplete` fires after the show animation has already started, setting `display: none` on a card that should be visible. GSAP's `gsap.killTweensOf(card)` before starting new animations would prevent this race.
