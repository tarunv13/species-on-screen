# Multi-species expansion with TMDB media integration (v2)

The four addressable issues from v1 have been resolved. The `.sp-loaded` class guard protects species page animations against mid-init JS failures. Filter animations kill in-progress tweens before starting new ones. The `statusClass` function sanitizes IUCN status strings with a whitelist regex. Image tags carry an `onerror` handler that replaces broken posters with a placeholder div.

**Watch for:** The global `window.addEventListener('error')` on species pages fires for *any* runtime error (including unrelated third-party scripts or CORS image errors), which could strip `.sp-loaded` and flash all animated sections to full opacity mid-scroll (likely). The `onerror` handler on img tags uses `this.outerHTML` assignment with inline single-quoted attributes — fragile if poster paths ever contain quotes (possible).

**Verdict**: APPROVED

## High-level view

The JS-failure safety net is the inverse of the homepage pattern: species pages add `.sp-loaded` only after successful data fetch and DOM render, rather than eagerly at DOMContentLoaded. This is more conservative. The risk is that the error listener is never removed, so any stray runtime error post-initialization (CORS image failure, browser extension) will strip the class and flash below-fold sections visible without animation.

<summary>Issues (2)</summary>

1. **Overly broad error listener on species pages** — `window.addEventListener('error')` removes `.sp-loaded` on *any* error event, including CORS image load failures and errors from browser extensions. A stray error mid-scroll would flash all below-fold sections to full opacity simultaneously. Scope the handler to only fire during initialization (remove it after `initAnimations()` completes), or use `{ once: true }`.
2. **onerror handler uses outerHTML with inline quotes** — The `onerror` attribute string uses escaped single quotes for class names. This works for current static CDN paths, but a helper function called from `onerror` would be more robust than inline HTML string construction inside an attribute.

## The `.sp-loaded` guard and its error listener

The species page adds `.sp-loaded` only after `renderSpeciesPage(data)` succeeds and immediately before `initAnimations()`:

```javascript
renderSpeciesPage(data);
document.body.classList.add('sp-loaded');
initAnimations();
```

The concern is post-initialization. The listener is never removed. A CORS error from a TMDB image load, a browser extension throwing, or any unrelated runtime error will also strip the class. Since species pages use `start: 'top 85%'` one-shot ScrollTriggers with no scrub, below-fold elements genuinely sit at CSS-applied `opacity: 0` until the user scrolls to them. Removing `.sp-loaded` mid-session causes those waiting elements to jump to visible without animation.

The homepage (`main.js`) has the same listener pattern but is less exposed because its ScrollTrigger animations use `scrub` mode with tight viewport ranges — elements animate in quickly and don't linger at opacity 0.

A targeted fix: remove the error listener after `initAnimations()` completes, or scope it with `{ once: true }` so it only fires for the first error (most likely the critical init failure).
