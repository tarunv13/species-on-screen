# Multi-species expansion from tiger prototype to 10-species platform (v2)

The Eco-Cinema Observatory evolves from a single hardcoded tiger profile into a data-driven multi-species site. A species registry serves as the single source of truth, feeding the 3D globe markers, a gallery on the index page, and navigation between 10 individual species profile pages. JSON data is pre-fetched and committed as static assets, loaded at runtime via fetch. The Vite config dynamically discovers species HTML pages for multi-page build. CI fix, SEO metadata, accessibility primitives, and a navigation breadcrumb round out the change.

The four issues flagged in v1 (incorrect taxonomy, innerHTML injection, duplicate nav, circular fallback) have all been addressed. Taxonomy data is now correct across all 10 JSON files. `species-page.js` applies `escapeHtml()` to all interpolated values. The static nav was removed from species HTML pages. The fetch script uses inline verified fallback data instead of reading from its own output.

**Watch for:** Nav breadcrumb injects `.textContent` into `innerHTML` without escaping (possible — low practical risk since source is a hardcoded `<h1>`). The `species-gallery.js` also uses `innerHTML` without `escapeHtml()`, though its data source is the committed registry module (confirmed — not exploitable today but inconsistent with the sanitization applied in `species-page.js`).

## High-level view

The architecture centers on one registry driving everything. Species pages code-split properly (5KB chunk), and the globe dynamically generates 31 markers from all species coordinates. The multi-page Vite config uses filesystem discovery, so adding a species requires only an HTML file and a JSON data file.

The sanitization story is split: `species-page.js` consistently escapes all values before innerHTML, but `species-gallery.js` and `nav.js` do not, relying on the fact that their data sources are committed static files. This creates a maintenance trap — a future contributor reading `species-page.js` would expect the same pattern elsewhere and might not realize `species-gallery.js` doesn't sanitize.

## Sanitization asymmetry between species-page and species-gallery

`species-page.js` defines a local `escapeHtml()` utility and applies it to every value interpolated into HTML strings. `species-gallery.js` builds card HTML via innerHTML using values directly from the imported `SPECIES` registry without escaping:

```javascript
card.innerHTML = `
  <h3 class="species-gallery__card-name">${species.commonName}</h3>
  <p class="species-gallery__card-scientific">${species.scientificName}</p>
  <p class="species-gallery__card-hook">${HOOK_SENTENCES[species.id] || ''}</p>
  <div class="species-gallery__card-accent" style="background-color: ${species.accentColor}"></div>
`;
```

The `accentColor` value is placed into a `style` attribute. If the registry ever contained a value like `red" onclick="alert(1)`, it would break out of the style attribute. Today the registry is a committed file with hardcoded hex colors, so this isn't exploitable — but the codebase sends mixed signals about its trust model.

Similarly, `nav.js` reads `.textContent` from the DOM and injects it into innerHTML without escaping.

The pragmatic fix: extract `escapeHtml` to a shared utility (e.g., `src/utils.js`) and import it in all three modules.
