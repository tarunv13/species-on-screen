## What the reconstruction established

- The atlas HTML pages are **thin shells**; `field-record.js` derives the place
  from the URL filename (`epr-vents.html` → `epr-vents` → `dwca/epr-vents/`) and
  renders everything from the DwC-A. For any non-Sundarbans place it builds
  **data-driven** steps (`buildGenericSteps()`) from the actors and
  interactions — no per-place authoring needed.
- The `ROLE` palette in `field-record.js` already contains **every**
  `trophicRole` used by the EPR archive (primary_producer, consumer, herbivore,
  predator, apex_predator, human_community). Nothing to add.
- `vite.config` **auto-discovers** atlas pages via `readdirSync(atlas/)`, so a
  new HTML file is bundled with no config edit.
- Sundarbans-specific code in the draw loop is guarded
  (`if (tiger && deer)`), so it is inert for EPR.

## Decisions / scope discipline

- **Biome backdrop left unchanged.** `biome-backdrop.js` `keyFor()` returns the
  generic `default` recipe for "Hydrothermal vent field". The atlas/research
  surface is a *light* painterly canvas by design (the darkness doctrine
  governs only the cinematic surface), so the default backdrop is tonally
  consistent with the other atlas pages — it is simply not vent-specific.
  Authoring an abyssal recipe (+ signature painter) is a design task that would
  touch a shared module beyond "follow the atlas pattern" and could not be
  visually verified in this headless flow. Logged as backlog item 3, not
  shipped blind.
- No atlas-architecture redesign, no new infrastructure. The change is one new
  page + one index entry + three additive per-place nav branches — the same
  extension shape every prior place used.
