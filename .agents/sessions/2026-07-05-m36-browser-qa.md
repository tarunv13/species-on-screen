## Behavioral acceptance — all PASS

1. **Follow web renders, laterally.** 9 `<section class="fr-node" id="fr-node-…" tabindex="-1">`
   actor nodes; 20 `.fr-follow` edges; **every** follow-target `#fr-node-<id>` resolves to a node
   **on the same page** — the follow is a same-depth lateral move (never a press-in/step-back).
2. **Follow action.** Activating a `.fr-follow` anchor sets `location.hash = #fr-node-<id>`,
   matches `:target` (node background `rgba(47,125,107,0.12)` = `--fr-accent-soft`), runs the
   `fr-follow-pulse` animation (`playState: running`), moves a11y focus to the node
   (`document.activeElement === node`, `focus({preventScroll:true})`), and grows `history.length`
   by **exactly one** (retraceable).
3. **Back / Forward retrace.** Real browser Back returns hash **and** `:target` to the prior node
   (OCC:3); Forward restores the later node (OCC:6). `:target` re-resolves on every
   `hashchange`/`popstate`.
4. **Reduced-motion safe.** The built stylesheet carries, under
   `@media (prefers-reduced-motion: reduce)`, `.fr-node.is-followed { animation: … none }`
   (`animation-name: none`), suppressing the pulse.

**Existing implementation satisfied every M36 acceptance criterion — no code changed.**

## Honest limitation observed (recorded, not fixed)

A **cold deep-link load** of `atlas/epr-vents.html#fr-node-<id>` does **not** restore
`:target`/scroll to the addressed node: on load `location.hash` is correct and the node exists, but
`:target` matches nothing and the page is not scrolled to it. Cause: the field record builds its
Sources panel (the follow web) **asynchronously** after a `fetch`, so the target element does not
exist at the browser's load-time fragment resolution, and the browser does not re-resolve the
indicated part when the node is later inserted (no navigation/`hashchange` fires). Warm navigation
(same-session follow, Back/Forward) is unaffected because those fire `hashchange`.

This is **not** an M36 defect — M36's acceptance is the *follow action* (verified PASS above). It is
an edge of M40's "follow… restorable via native `:target` scroll" claim on an **async** surface.
M40 is **closed and audit-accepted**, and its browser QA verified the `#claim-N` restore on the
evidence ledger (static HTML, restores correctly); the `#fr-node` cold-restore on the async field
record was never one of M40's four verified criteria. Per the frozen scope discipline (do not
relitigate closed milestones, no redesign, smallest reviewable change, do not continue to the next
milestone) it is **recorded as an R1 follow-up**, not fixed here.
